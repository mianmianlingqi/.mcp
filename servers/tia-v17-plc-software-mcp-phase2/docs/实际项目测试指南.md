# TIA Portal V17 PLC-Software MCP Phase2 实际项目测试指南

> 适用包：`TIA_V17_PLC_Software_MCP_Phase2_Deliverable_20260608_101552`  
> Profile：`plc-software-v17-phase2`  
> 最新封包验证：`success`，工具面 `74/74`，E2E `success`  
> 建议用途：在真实 V17 工程副本上做 PLC-Software 能力验证，不直接操作生产原件。

## 1. 测试原则

- 只测试 `.ap17` 工程副本，不直接打开生产原工程。
- 测试前先关闭多余 TIA Portal，只保留必要实例，避免内存不足或项目互锁。
- 首轮只做只读检查，确认能打开、附着、读取工程树和 PLC 软件树后，再做导入、编译、保存类操作。
- 涉及写入的工具必须在测试副本上执行，并在每个阶段手动或脚本保存一份备份。
- 不测试 Online 下载、上线监控、写值、HMI、Unified、Reports。这些能力不在 Phase2 暴露面内。

## 2. 环境要求

- Windows 机器已安装 TIA Portal V17。
- 当前 Windows 用户已加入 `Siemens TIA Openness` 用户组。
- 已安装 PowerShell 7，命令统一使用 `pwsh -NoProfile -ExecutionPolicy Bypass -File ...`。
- 默认 HTTP 地址：`http://127.0.0.1:8770/mcp`。
- 默认 API key：`codex-test-key`。
- 建议可用内存不少于 16 GB，复杂项目建议 32 GB 以上。

## 6. 实际项目只读冒烟测试

推荐先用 MCP 客户端按下面顺序调用：

1. `Bootstrap`
2. `Connect`
3. `OpenProject(path="测试副本 .ap17 路径")`
4. `GetState`
5. `GetProject`
6. `GetProjectTree`
7. `GetSoftwareTree`
8. `GetSoftwareInfo`
9. `GetBlocks`
10. `GetBlocksWithHierarchy`
11. `GetTypes`
12. `GetPlcTagTables`
13. `GetPlcWatchTables`
14. `GetPlcExternalSources`
15. `GetTechnologyObjects`

只读冒烟通过标准：

- `OpenProject` 返回成功，并且绑定到目标测试副本路径。
- `GetProjectTree` 能看到真实设备。
- `GetSoftwareTree` 能看到 PLC 软件节点，例如 `PLC_1` 或项目中的实际 PLC 名称。
- 查询工具不返回解析异常、不超时、不误报 `not found`。

如果 `OpenProject` 报 `Another project is already open`：

- 先确认 TIA UI 是否已经打开了另一个工程。
- 如果前台已经打开同路径测试副本，优先调用 `AttachToOpenProject` 或重新调用 `OpenProject(path)` 观察是否能附着。
- 仍失败时，保存并关闭 TIA UI 中的工程，再重启 MCP 服务后重试。

## 8. 写入类测试

写入测试必须在工程副本上做。建议每组测试前复制一个新副本。

推荐最小写入闭环：

1. `SaveProject`
2. `PlcBuildAndImport(kind=tagtable)`
3. `PlcBuildAndImport(kind=udt)`
4. `PlcBuildAndImport(kind=globaldb)`
5. `ImportPlcExternalSource`
6. `GenerateBlocksFromExternalSource`
7. `CompileAndDiagnosePlc`
8. `SaveProject`
9. `CloseProject`
10. 重新 `OpenProject`
11. `GetBlocks / GetTypes / GetPlcTagTables` 读回确认

FC / FB 写块注意：

- V17 推荐路径是外部 SCL 导入，再执行 `GenerateBlocksFromExternalSource`。
- 不建议把 FC / FB 直接写成块 XML 再导入。
- 如果要写 GlobalDB，必须使用已修复的 V17 兼容 XML 生成逻辑。

写入通过标准：

- 导入返回成功。
- 编译通过，`CompileAndDiagnosePlc` 无失败诊断。
- 保存后关闭重开，仍能读回新增对象。
- 不出现 `Another project is already open`。

## 9. Technology Object 测试

Phase2 已纳入 TO 增强项：

- `CreateTechnologyObject`
- `GetTechnologyObjects`
- `ExportTechnologyObject`
- `ExportTechnologyObjectsToDirectory`
- `ImportTechnologyObject`
- `ImportTechnologyObjectsFromDirectory`

推荐基线：`1211C DC/DC/DC + PID_Compact`。

测试顺序：

1. 打开测试副本。
2. 调用 `GetTechnologyObjects`，确认当前 TO 列表。
3. 如果工程内已有 PID_Compact，先执行 `ExportTechnologyObject`。
4. 如果工程内没有 TO，可尝试 `CreateTechnologyObject` 创建 PID_Compact。
5. 导出 TO XML 到 `_mcp_exports`。
6. 在新的工程副本中调用 `ImportTechnologyObject`。
7. 再调用 `GetTechnologyObjects` 读回。
8. 批量导入目录用 `ImportTechnologyObjectsFromDirectory` 验证。

TO 通过标准：

- `GetTechnologyObjects` 能读到目标对象。
- `ExportTechnologyObject` 实际落盘 XML。
- `ImportTechnologyObject` 成功后能再次读回。
- 如果 `CreateTechnologyObject` 对某类 TO 不稳定，可将该类创建标记为 gated，但导入官方风格 XML 路径仍可验收。

1. 保存 MCP 返回原始 JSON。

4. 关闭测试副本工程。
5. 删除失败副本，重新从生产原件复制一份干净副本。
6. 如果是工具问题，再用同一输入复现一次，保留最小复现工程和导入文件。

## 13. 现场判定标准

可以继续扩大测试的情况：

- 只读冒烟全部通过。
- 导出类工具能稳定落盘。
- 写入类工具只在副本里操作，编译和重开读回都通过。
- MCP 服务停止脚本能正常收尾。

需要暂停排查的情况：

- 工程路径绑定不对。
- 出现 `Another project is already open` 且重启服务后仍复现。
- `OpenProject` 成功但 `GetProjectTree` 看不到真实设备。
- 写入后编译失败且错误不明确。
- 保存重开后新增对象丢失。
- TIA Portal 内存占用过高或 UI 无响应。
